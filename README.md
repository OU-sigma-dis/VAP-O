# VAP-O: Onset Proximity for Turn-Taking Timing

Reference implementation of **Onset Proximity**, a per-speaker regression target that
lets a Voice Activity Projection (VAP) model estimate *when* the next speaker will start,
not only *whether* a turn shift is imminent.

> **Onset Proximity: A Regression Target for Predicting When the Next Speaker Will Start in Spoken Dialogue**
> Kazuyo Onishi, Hien Ohnaka, Koichiro Yoshino. IEEE Access, 2026 (to appear).

The label rises linearly toward each speaker's next speech onset and peaks at the onset,
so onset timing can be read out by peak detection. VAP-O keeps the standard channel-separated
VAP backbone (frozen CPC features + causal ALiBi Transformer) unchanged and replaces only the
output head: the 256-class softmax becomes a per-speaker onset-proximity regression head.

---

## Context

- **What this repo is.** Training and evaluation code for VAP-O and for the 256-class VAP
  baseline it is compared against, plus the analysis scripts that reproduce the paper's tables
  and figures.
- **What it is not.** It does not redistribute the Switchboard corpus (LDC-licensed) or the
  pretrained CPC weights; both must be obtained separately (see *Data and pretrained weights*).
  Trained checkpoints, logs, and cached results are not included.

## Data and pretrained weights

These are **not** included and must be prepared locally.

1. **Switchboard corpus** (LDC97S62). Obtain from the LDC. We use sessions
   `sw02001`–`sw02184` as a fixed test set; the rest is split 90/10 (seed 42) into train/val.
2. **Pretrained CPC encoder.** Download the CPC checkpoint used by prior VAP work and place it
   under `models/` as `pre_trained_model.pt`. The encoder is kept frozen during training.
3. **CPC features.** Pre-extract 100 Hz CPC features:
   ```bash
   python scripts/extract_cpc_features.py   # writes features next to the dataset CSVs
   ```
4. **Onset-proximity labels** are generated by the DataModule at load time; the horizon is
   `H = 3.0` s.

> **Paths.** Scripts reference absolute dataset paths (e.g. `.../switchboard/vap-o_dataset/`).
> Edit the path constants at the top of the training/evaluation scripts to match your setup.

## Usage

### Training

```bash
# VAP-O (audio-only, GPT-Stereo backbone, onset-proximity target)
python trains/train.py --vap_use_stereo 1 --vap_use_text 0 --vap_use_filler 0 \
    --seed 42 --opt_saved_dir ./output/checkpoints_vapo --device mps

# 256-class VAP baseline (same backbone and protocol)
python trains/train_baseline.py --seed 42 --save_dir ./output/checkpoints_baseline
```

Early stopping monitors the validation loss. The paper reports three seeds `{42, 43, 44}`.

### Reproducing the paper

Each script writes a Markdown report under `reports/`.

| Result | Script |
|---|---|
| Offline onset-timing accuracy and paired tests (Tables 2–3) | `scripts/final_stats.py` |
| Timing-aware readouts of the VAP baseline | `scripts/vap_timing_readouts.py` |
| Pseudo-online simulation (Table 4) | `scripts/online_sim.py` |
| Event-detection F1 (Table 5) | `scripts/multi_seed_eval.py` |
| Multi-seed aggregation (mean ± std) | `scripts/multi_seed_stats.py`, `scripts/multi_seed_online.py` |
| Inference latency | `scripts/benchmark_latency.py` |
| Qualitative onset-proximity traces (Fig. 4) | `scripts/visualize_predictions_simple.py` |

Onset timing is read out by locating the global maximum of the onset-proximity signal within
the prediction region (argmax), which the label's design implies. The online simulation never
accesses the true onset and reports precision, recall, false-alarm rate, and early/late bias.
